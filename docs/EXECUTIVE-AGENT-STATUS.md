# Executive Agent implementation status

This document distinguishes implemented foundations from unavailable integrations. The existing Sentinel X command center and deterministic tool router remain the execution brain; there is no second assistant or new navigation tab.

| Area | Current behavior | Status / limit |
|---|---|---|
| Outcome-oriented execution | Natural-language routing to local tools; multi-step read-only network and performance diagnostics; progress, bounded checkpoints, cancellation, evidence and cautious completion wording. | Partial: deterministic supported workflows, not a general planner for every goal. |
| Diagnosis and repair | Read-only CPU/RAM/GPU/process/network evidence; one bounded network retry; no arbitrary optimization. | Diagnosis supported for selected symptoms. Repair is not attempted when measurements cannot justify a specific reversible change; approvals remain required for consequential work. |
| Task graph / resume | Bounded local checkpoints persist validated acyclic step dependencies; independent read-only process/network probes can run concurrently; interrupted supported diagnostics can be rerun from the beginning; waiting download checkpoints are rechecked against recently changed matching files; cancellation stops future steps. | This is not a general-purpose dependency-graph scheduler and does not exactly resume an arbitrary tool step. Completed effects are not rolled back. |
| Black Box / incidents | At most 180 two-second CPU/RAM/GPU samples in RAM (about six minutes); up to 12 user-requested event markers in RAM; bounded, restrained threshold alerts with configurable duration/cooldown; focus mode suppresses notices. | No temperature, VRAM, clocks, FPS/frametime, per-app network transfer, or game-server packet-loss measurements. A process exit is not labeled a crash without evidence. |
| Watchers | Explicit download-stability, performance and CS2-exit watches; user-defined bounded CPU/RAM/GPU-duration and stable-download rules with local notification actions; status/removal commands; privacy-gated local persistence. Example: „powiadom mnie gdy CPU przekroczy 90% przez 30 sekund”, „automatyzacje”. | Rule triggers and actions use a strict whitelist (notification only); no arbitrary actions or Windows notification provider. |
| Contextual memory | Working task context; bounded conversation history; source/confidence/freshness/confirmation metadata; query-relevant retrieval; durable profile preferences; private-mode persistence gates. | Confidence describes source quality, not objective truth. Private mode does not control remote-service logs. |
| Research / skills | Explicit topic-learning requests research public web pages when external networking is enabled, then create an editable source-backed local brief or a clearly unverified local-only draft. | This creates notes, not model training. Search providers may log queries; no proxy/VPN anonymity is claimed. |
| Reminders / daily context | Local tasks and one-shot reminders; daily briefing; missed reminders surface on next launch; user-defined notification-only event rules. | Timed reminder delivery requires Sentinel to be running; no multi-action or arbitrary event-triggered routines. |
| Clipboard / screen context | Clipboard text is read only on explicit commands, capped, obvious credentials are blocked, and explanation/translation uses only local Ollama. Screen questions use bounded UI Automation labels on explicit request. | No image/OCR/screenshot vision or editable-field reading; the limited phone Bridge does not provide screen vision. Clipboard content can still influence the resulting answer; apply conversation privacy settings. |
| Readiness / recovery | Existing readiness checks report storage, memory/tasks when registered, microphone, ASR files and local Ollama independently; supported diagnostic steps isolate tool failures and continue with remaining evidence. | Reports recovery guidance; does not automatically restart providers or mutate system configuration. |
| Universal routing | The existing toolbox routes bounded arithmetic to a decimal parser (integer multiplication also has a BigInteger cross-check), freshness-sensitive weather/prices/specifications/documentation to sourced web research, and authorized device commands to Home Assistant. | No arbitrary code execution, and no new assistant/tab. Current web summaries are extractive and not independently verified; local-only mode blocks external research. |
| Devices / pairing | Optional Home Assistant REST adapter reads only entities from the explicitly configured instance, supports manual aliases for lights/media players/remotes, and verifies supported state changes by readback. Alias/entity/domain mappings can persist separately from chat history; credentials are read from environment variables and are not written to the registry. | Setup uses `SENTINELX_HOME_ASSISTANT_URL` and `SENTINELX_HOME_ASSISTANT_TOKEN`; no LAN scan, credential prompt, or security bypass. Generic switches and scenes are intentionally excluded because they may affect hazardous or multiple devices. Requires configuration and owner pairing; not yet compiled or tested. |
| Phone Bridge | Opt-in .NET TCP/TLS server binds private IPv4 addresses only; one-time pairing code, certificate pinning, DPAPI-protected phone hashes/certificate, Android Keystore token storage, replay/rate limits, named skill registry and bounded JSON macros. Android companion source is under `phone-android/`. | No public bind, router/firewall changes, WAN relay, shell/script endpoint, arbitrary paths, or default listener. PC status, allowlisted app launch, lock (unverified), downloads and supported HA controls only. Screenshot/file transfer/shutdown/restart are refused. Android APK and Windows build/tests have not been produced/run; see `docs/PHONE-BRIDGE.md`. |
| Coding / mobile apps | Three bounded Windows templates generate source only; a separate bounded Android generator provides counter, local notes, and checklist projects. A manual GitHub Actions workflow compiles selected Android templates into debug APK/source artifacts; projects request no Internet permission. | Sentinel does not run generated code or build an EXE locally. APKs are debug-signed for device testing, not Play Store releases; no GitHub token is stored. See `docs/MOBILE-APP-GENERATOR.md`. |
| Phone calls | Tool refuses unless a real provider verifies a completed call and supplies a transcript. | No Android SIM/telephony/audio provider exists in this repository; the new phone companion controls Sentinel but does not place calls, and no calls are simulated. |
| Undo / verification | Action evidence distinguishes verified, unverified, failed and cancelled outcomes. The latest supported file create/edit/copy/move/rename or empty-folder creation in a process can be undone after HIGH-risk approval; content/path hashes are rechecked before reversal and the resulting state is read back. Undo is bounded to one process-local record; text snapshots are at most 1 MiB and hash-checked file operations at most 64 MiB. | Stale or ambiguous state is refused; folders are removed only when empty and never recursively. Arbitrary external-app, operating-system, or interrupted multi-step effects are not reversible through this path; no universal transaction log exists. |

## Validation

Regression coverage was added for confidence-preserving migrations, explicit clipboard handling, Watch policy, bounded event-condition-action rules and privacy-gated persistence, interrupted-goal safety, download checkpoint reseeding, readiness routing, source-only program generation, calculator routing, automatic freshness-sensitive research, Home Assistant discovery/pairing/state verification and alias-only persistence, named phone-skill routing and safe-macro validation, approval-gated exact-byte file undo, reversal of created/copied/moved files and empty folders, stale-state refusal, and mutation blocking while undo approval is pending. These tests have **not** been run in this environment: the .NET SDK is unavailable. `git diff --check` is the available validation and must be rerun after subsequent edits.
